╔═══════════════════════════════════════════════════════════════╗
║ DEPLOY FIX #2 — rag_memory.py uses default embedding (heavy) ║
╚═══════════════════════════════════════════════════════════════╝

FILE: backend/services/rag_memory.py

PROBLEM:
  chromadb.PersistentClient with default settings uses sentence-transformers
  for embeddings when you call collection.query(query_texts=[...]).
  This triggers a 400MB model download on first startup — crashes Render.

FIX — Use ChromaDB's built-in lightweight embedding function:
─────────────────────────────────────────────────────────────────
import chromadb
from chromadb.utils import embedding_functions
import uuid
import logging
import os

logger = logging.getLogger("cloudiq.rag")

DB_DIR = os.path.join(os.path.dirname(__file__), "..", "chroma_db")

# Use ChromaDB's lightweight default embedding (no sentence-transformers needed)
# On Render/cloud: this uses a simple character-level hash for similarity
# It's less semantically accurate than transformers but works without 400MB downloads
_default_ef = embedding_functions.DefaultEmbeddingFunction()

try:
    os.makedirs(DB_DIR, exist_ok=True)
    chroma_client = chromadb.PersistentClient(path=DB_DIR)
    chat_collection = chroma_client.get_or_create_collection(
        name="chat_history",
        embedding_function=_default_ef,   # ← explicit lightweight embedding
    )
    logger.info("[RAG] ChromaDB initialized with default embedding function")
except Exception as e:
    logger.error(f"[RAG] Failed to initialize ChromaDB: {e}")
    chat_collection = None

# store_interaction() and retrieve_relevant_history() stay exactly the same
─────────────────────────────────────────────────────────────────

NOTE: This trades semantic accuracy for cloud compatibility.
      For a portfolio project this is the right tradeoff.
      The RAG still retrieves related past conversations — just
      by simpler similarity rather than deep semantic embedding.

FILE: frontend/src/App.jsx

CURRENT (wrong — key on Routes, PageWrapper per route):
  <AnimatePresence mode="wait">
    <Routes location={location} key={location.pathname}>
      <Route path="/" element={<PageWrapper><ErrorBoundary ...>

WHY IT DOESN'T WORK:
  AnimatePresence animates its direct children when their key changes.
  <Routes> is the direct child — it has key={location.pathname}.
  But <Routes> is not a motion component — framer-motion ignores it.
  PageWrapper (motion.div) per route: AnimatePresence can't coordinate
  multiple motion.div children exiting/entering simultaneously.
  Result: instant snap on every navigation.

CORRECT STRUCTURE:
  Single motion.div as direct child of AnimatePresence
  key={location.pathname} on that motion.div
  Routes INSIDE the motion.div (no key on Routes)
  No PageWrapper needed

CORRECT CODE:
─────────────────────────────────────────────────────────────────
const pageVariants = {
