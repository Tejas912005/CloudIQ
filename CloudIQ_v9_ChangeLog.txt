MODIFIED: backend/requirements.txt
  REMOVED:  sentence-transformers  (was 400MB — crashed Render free tier RAM limit)
  REMOVED:  langchain-ollama       (requires local Ollama server, unavailable on cloud)
  REMOVED:  langchain              (not imported anywhere in actual code)
  REMOVED:  langchain-community    (not imported anywhere in actual code)
  REMOVED:  crewai                 (not used anywhere in the codebase)
  KEPT:     fastapi, uvicorn, sqlalchemy, psycopg2-binary, numpy, scikit-learn,
            pandas, scipy, networkx, google-genai, chromadb, python-multipart
  WHY:      These removed packages caused Render to fail during build or exceed the
            512MB RAM limit on startup. The lean requirements.txt deploys in ~3 minutes.

MODIFIED: backend/services/rag_memory.py
  CHANGED:  get_or_create_collection() now passes embedding_function=_default_ef
  ADDED:    from chromadb.utils import embedding_functions
  ADDED:    _default_ef = embedding_functions.DefaultEmbeddingFunction()
  WHY:      Without an explicit embedding function, ChromaDB tries to download
            sentence-transformers (400MB) on first startup — crashes Render.
            The DefaultEmbeddingFunction is a lightweight built-in character-level
            hash. Less semantically accurate but works on any cloud server instantly.

VERIFIED: backend/core/config.py
  STATUS:   Already correct — CORS_ORIGINS reads from environment variable with
            localhost fallback. No change needed.
            Production URL should be set in Render dashboard env vars.

VERIFIED: frontend/src/lib/api.js
  STATUS:   Already uses import.meta.env.VITE_BACKEND_URL || '' correctly.
            All fetch() calls prepend the API base URL.
            No change needed. In production, set VITE_BACKEND_URL in Vercel env vars.

MODIFIED: frontend/src/components/dashboard/WhatIfSimulator.jsx
  LINE 14:  const idleCount = platform.rawSummary?.idle_count || 0;
  LINE 15:  const totalCost = platform.rawSummary?.total_monthly_cost || 0;
  REMOVED:  .resources. nesting that does not exist in the API response
  REMOVED:  || 5 fake hardcoded fallback
  WHY:      /api/analyze returns idle_count and total_monthly_cost at the top level
            of the response object. The .resources. sub-object never existed. The
            || 5 fallback was hiding the bug and displaying fake data in the UI.
            The What-If slider "You Save" calculation was always wrong as a result.

MODIFIED: frontend/src/App.jsx
  DELETED:  PageWrapper component (was a motion.div per route — broken pattern)
  CHANGED:  AnimatedRoutes — key={location.pathname} moved from <Routes> to <motion.div>
  CHANGED:  <Routes> now has NO key prop
  CHANGED:  pageVariants — simplified to 220ms fade + 10px y-shift (was 500ms blur)
  REMOVED:  Blocking auth gate (if (!session) return <AuthModal />) — auth now in TopHeader
  REMOVED:  Supabase session check in App.jsx (moved to useCloudStore.initAuth)
  WHY:      AnimatePresence animates its direct children when their key changes.
            <Routes> is not a motion component — framer-motion ignores it completely.
            The fix is to make <motion.div key={pathname}> the direct child, with
            <Routes> inside it. This was reported as broken 4 times.

MODIFIED: frontend/src/store/useCloudStore.js
  ADDED:    import { supabase } from '../lib/supabase'
  ADDED:    user: null          — holds authenticated Supabase user object
  ADDED:    authLoading: true   — true while checking existing session
  ADDED:    initAuth()          — reads existing session, sets up onAuthStateChange listener
  ADDED:    signOut()           — calls supabase.auth.signOut() and clears user state
  WHY:      Auth state was half-built with no Zustand integration. Components had no
            way to know if a user was logged in. The initAuth action checks for an
            existing session on load and listens for future auth changes in real-time.

MODIFIED: frontend/src/context/CloudIQContext.jsx
  ADDED:    useCloudStore.getState().initAuth() at the top of the startup useEffect
  WHY:      initAuth() must be called exactly once when the app boots. CloudIQContext
            is the ideal place since it wraps the entire app and runs on first mount.

MODIFIED: frontend/src/components/layout/TopHeader.jsx
  ADDED:    import { LogIn, LogOut, User } from 'lucide-react'
  ADDED:    import AuthModal from '../auth/AuthModal'
  ADDED:    import { useCloudStore } from '../../store/useCloudStore'
  ADDED:    user = useCloudStore(state => state.user)
  ADDED:    signOut = useCloudStore(state => state.signOut)
  ADDED:    [showAuth, setShowAuth] — controls AuthModal visibility
  ADDED:    Auth UI in RIGHT section of header:
              - If logged in: avatar circle + email prefix + LogOut button
              - If not logged in: "Sign In" button with accent color
  ADDED:    {showAuth && <AuthModal onClose={...} />}
  WRAPPED:  return in a React Fragment (<>) to allow sibling modal render
  WHY:      There was no visible login button anywhere in the app. Users had no way
            to sign in or out without knowing to look for a hidden modal.

MODIFIED: frontend/src/components/auth/AuthModal.jsx
  CHANGED:  Props from { onAuthSuccess } to { onClose }
  ADDED:    useEffect with supabase.auth.onAuthStateChange → auto-closes on SIGNED_IN
  ADDED:    Backdrop overlay (fixed inset-0, rgba(0,0,0,0.65), blur(8px), z-index 100)
  ADDED:    Click backdrop to close (onClick={onClose} on backdrop, stopPropagation on modal)
  ADDED:    Close X button (position absolute, top-right corner of modal box)
  ADDED:    Loading state — button disabled + spinner while request in progress
  ADDED:    Error display — red banner shows error.message if auth fails
  ADDED:    Sign-up success message — prompts user to check email for verification
  IMPROVED: All styles use CSS variables (no hardcoded colors)
  WHY:      The modal had no way to close itself, no backdrop, no X button, and no
            auto-close after successful login. It was functionally broken.
